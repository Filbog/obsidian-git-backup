 - **one-to-one** - like a user and ID - each user should have one unique ID. In real world: a person and their passport. In web dev practice, one-to-one relationships are rather rare
 - **one-to-many** - most common. Like one book can have many reviews
 - **many-to-many** - like authors and books - one author can have many books, one book can have many authors
